# Pyroduct 模型速查

把两篇中文哲学文本建模为可运行、可测试的 MoonBit 状态机族。「原文直述」与
「模型整理」是本模型的两层出处，报告里逐处标注：`report` 的「派生表与持久度」
一节给全表，`slots` 逐槽给标注。页码出处只在四处印出来（`multi`／`group`／
`society` 的 gloss 带 P.xx，`intuition` 是 evolution 那三处）——主体机
自己的表只有原文措辞，`report`／`slots`／`naming`／`spec` **没有**页码字段。
本技能只做**读法纪律**与**取事实的路径**，模型语义一条都不在插件里——全在模块内，
随模块定版与门禁。

## 工具面（MCP `pyroduct`）

| 工具 | 用途 |
|---|---|
| `pyroduct_faces` | 面目录：28 个面各一行读法，附模型版本与「这次答案来自内置快照还是本地 checkout」。**先调它**再选面。 |
| `pyroduct_face(kind)` | 跑一个面，返回该面报告全文。`kind` 取面目录里的名字。 |
| `pyroduct_gates` | 门禁套件（`moon check` + `fmt --check` + `test`，129 个测试）。需要配置了 checkout；只有内置快照时它如实说「不可用」而不报错。 |

要跑**呈现层**（`viz` 合成页、`journey` 行程视图、嵌套视图、`all` 组合）时工具面
没有这些面：它们是渲染不是模型事实，去有 checkout 的地方用
`moon run cmd/main -- viz` 一类命令（见 [参考/CLI 全表](references/cli.md)）。

## 取事实的次序

1. 先 `pyroduct_faces` 定位面 → 2. `pyroduct_face` 一次取全文 → 3. 引用具体位置时
   取 `naming` 那一行（定名｜原文名｜原文措辞）；要交代出处层，取 `report` 的
   「派生表与持久度」或 `slots` 的逐槽标注；引用要页码就去 `multi`／`group`／
   `society`（那几面的 gloss 带 P.xx），主体机的面没有页码可引。
4. 数字对不上就以工具输出为准：报告里带总数（34/53/11/8/49/272/228/31），与本文件
   冲突时说明模型已变，不要两套数字并存。

## 读法纪律

- **未定不是失败**：`step` 返回 未定（多条出路并存）时，机器不替主体决断；
  在 `evolution::run_cycle` 里按双诚之比裁决。回答时别说「卡住」。
- **无路是数据**：228 个无路组合是模型的如实输出（`loop` 面的缺口表），不是缺页。
  不编造不存在的迁移。
- **反馈由闸门给出**：`cycle` 演示里缺省主体停在「自身」的持存自环，原因是
  修习与开放两个候选都过不了因果闸门（θ̂=0.012，95% CI 跨零；朴素差 0.467
  是选择偏误）。这是「没有证据就不前进」的正确读法，不是缺陷。
- **结构不强迫活性**：`buchi` 面里 11 处停滞位有 10 处守词不被接受；公平性假设
  （主体终究要动）住在进化层的双诚之比与闸门里，不在机器里。
- **出处两层**：状态／迁移／措辞是原文直述；驱动槽八分、循环映射、五条分析面是
  模型整理。引用时注明属于哪层，并说清是从哪一面读到的标注。
- **认出不是重算**：循环报告里「同判·不重裁」是「持存」的取回（背景直觉），
  回溯持平是「揭蔽」的通过——出处见账本的首裁回合；直觉永不宣称终局（不封闭）。
- **绊线是零**：`audit` 面的「未预期」必须为 0；非零就是机器被改坏了，先查再答。
  `fleet` 面把同一绊线扩到群体机与社会机（那两台**不设豁免**：真表上零发现，
  预留「已知设计」口子等于给未来的改坏留后门）。若有人拿「三鉴报 0 条」当证据，
  用 `mutants` 面看那 18 处故意的破坏是不是逐处被抓——0 条发现与什么都看不见，
  在报告上长得一模一样。
